Detector de validación de "aud" rota (fail-open)

Un servidor que verifica un JWT/token OAuth puede tener una validación del claim "audience"/"aud" (para quién se emitió el token) rota de forma sutil: un catch() que silencia el error de audiencia y deja pasar la petición igual, una rama de "no coincide" que solo loguea en vez de rechazar, o todo el chequeo condicionado a una bandera de configuración que puede estar apagada. En los tres casos el código "tiene" una validación que un lector apurado asumiría que funciona, pero que en la práctica deja pasar un token emitido para OTRO servidor (confused deputy). Motivado por CVE-2026-14541 (confusión de audiencia OAuth en MCP). Pegá acá el código del verificador de tokens de tu servidor.

De uso libre

Es un análisis estático por patrones de texto — no ejecuta nada. Todo el análisis corre en tu navegador; el código que pegás acá no se envía a ningún lado.

Pegá el código y presioná "Analizar código".
Distinto del chequeo superficial de detect_token_passthrough_risk (esa herramienta solo mira si la palabra "audience"/"aud" aparece cerca de un jwt.verify/decode). Esta herramienta mira el VERIFICADOR PROPIO del servidor con más profundidad: si la validación que SÍ existe realmente bloquea la petición cuando la audiencia no coincide. No reemplaza un analizador de sintaxis (AST) real ni una auditoría de seguridad formal.
