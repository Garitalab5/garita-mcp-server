Detector de sesiones validadas solo por ID

Un servidor que busca una sesión solo por el ID que trae la petición (sessions[sessionId], sessionStore.get(sessionId)) y después confía en ella sin comparar ningún campo de dueño/principal contra quien está pidiendo ahora, es vulnerable a secuestro de sesión: quien consiga ese ID — adivinándolo, robándolo de un log o de una URL compartida — queda autenticado como el dueño real, sin que el servidor note nada raro. Motivado por CVE-2026-52869 (CVSS alto): un servidor MCP resolvía sesiones solo por el identificador recibido, sin ningún vínculo adicional con la identidad de quien la presentaba. Regla secundaria de la misma CVE: un ID de sesión generado con poca entropía (Math.random(), un contador, solo Date.now()) es adivinable por fuerza bruta. Pegá acá el código que busca o genera sesiones.

De uso libre

Es un análisis estático por patrones de texto — no ejecuta nada. Todo el análisis corre en tu navegador; el código que pegás acá no se envía a ningún lado.

Pegá el código y presioná "Analizar código".
Distinto del Centinela de Autenticación (detect_missing_auth_risk): ahí no se verifica NADA; acá SÍ hay una sesión y SÍ se la busca, pero la búsqueda por ID no es, por sí sola, prueba de que quien la presenta es su dueño legítimo (CWE-384). No reemplaza un analizador de sintaxis (AST) real ni una auditoría de seguridad formal. Límite conocido: si el vínculo de dueño se verifica en una función aparte definida lejos de la búsqueda, puede no detectarse.
