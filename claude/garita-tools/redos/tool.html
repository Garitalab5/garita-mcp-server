Detector de backtracking catastrófico en expresiones regulares

Una expresión regular con cuantificadores anidados (ej. (a+)+, (\s*\w+)*, (a|a)*) puede quedar atascada procesando un solo string durante segundos, minutos o para siempre: el motor de regex prueba exponencialmente muchas formas de agrupar la misma entrada antes de fallar. Si esa expresión se aplica sobre una entrada sin tope de longitud que viene de quien llama a la herramienta, un solo mensaje cuidadosamente armado basta para colgar el proceso entero — una denegación de servicio (ReDoS, CWE-1333) sin necesidad de ninguna otra vulnerabilidad. Motivado por CVE-2026-0621 (CVSS 7.5): un regex de validación vulnerable, alcanzable sin autenticación, en un servidor/herramienta MCP ampliamente desplegado. Pegá acá el código que compila o aplica una expresión regular y revisá si le falta protección.

De uso libre

Es un análisis estático por patrones de texto — no ejecuta nada ni mide tiempos reales de backtracking. Todo el análisis corre en tu navegador; el código que pegás acá no se envía a ningún lado.

Pegá el código y presioná "Analizar código".
No reemplaza un analizador de sintaxis (AST) real, un motor de verificación de regex (ej. "safe-regex") corriendo de verdad, ni una auditoría de seguridad formal — mismo enfoque y mismas limitaciones que el Escudo de Código Dinámico y el Escudo de Inyección SQL. CVE-2026-0621 documenta también la variante de regex compilado dinámicamente a partir de una fuente no controlada por el desarrollador, cubierta acá como hallazgo separado.
