Detector de SSRF
Peticiones HTTP sin validar que un atacante usa para alcanzar recursos internos

Una herramienta que le hace una petición HTTP a una URL controlada por el agente puede terminar usada para que el servidor pida, en su nombre, un recurso interno: el endpoint de metadata de la nube (roba credenciales temporales de AWS/GCP/Azure), un panel de administración, o cualquier servicio en la red privada. Documentado en un censo real de 2026 sobre 9.695 servidores MCP: SSRF fue el 8.5% de los 4.982 problemas encontrados, dentro de un 60% de servidores con algún problema de seguridad.

Cómo se usa: pegale a esta herramienta el código de la función que hace la petición HTTP — revisa falta de validación de la URL, IPs privadas o de metadata hardcodeadas, TLS desactivado, redirecciones sin revalidar, y ausencia de restricción de esquema.

Detector de Path Traversal
Operaciones de archivo sin validar que dejan escapar rutas fuera del directorio permitido

Una herramienta que lee, escribe o borra un archivo usando una ruta que depende de una entrada externa puede terminar accediendo a cualquier archivo del sistema — credenciales, llaves SSH, configuración — si esa ruta no se valida. Es la categoría más grande del censo 2026 de servidores MCP (17.7% de 9.695 servidores, 880 casos) y el patrón exacto detrás de CVE-2026-40576 (CVSS 9.4), una falla sin autenticar en un servidor MCP de Excel.

Cómo se usa: pegale a esta herramienta el código de la función que lee, escribe o borra un archivo — revisa falta de validación contra secuencias "../", rutas sensibles hardcodeadas (/etc/passwd, llaves SSH, credenciales) y ausencia de un rechazo explícito de rutas absolutas.

Escudo de Tokens
Reenvío de tokens OAuth sin validar (token passthrough / confused deputy)

Un middleware o herramienta MCP que recibe un token de autorización y lo reenvía tal cual hacia otra API — o deja pasar la petición sin validarlo — es el clásico "confused deputy" que la propia especificación de MCP prohíbe explícitamente. Caso real de mayor perfil: CVE-2026-48039 (Meta Ads MCP, CVSS 9.1 crítico), donde un middleware reenviaba peticiones sin validar el header Authorization y filtraba el token de larga duración del operador. El mismo patrón aparece en CVE-2025-6514 (CVSS 9.6) y CVE-2026-27826 (CVSS 8.2).

Cómo se usa: pegale a esta herramienta el código del middleware o la función que maneja el token — revisa reenvío sin validar hacia otra llamada saliente, ausencia de verificación antes de dejar pasar la petición, verificación de JWT sin el claim "audience", y tokens expuestos como parámetro de una URL.

Escudo de Secretos
Credenciales/API keys embebidas en texto plano en código y configuración

Una API key, un token o una contraseña escrita tal cual en el código o en un archivo de configuración queda expuesta a cualquiera que vea ese archivo. Un estudio real de Hush Security (septiembre 2026) escaneó ~82.000 archivos de configuración MCP públicos: 1 de cada 8 credenciales estaba embebida en texto plano, el 53% con acceso a nivel de toda la organización, y el 80% de las que tenían política de expiración nunca expiraban por defecto. También documentado por Trend Micro (48% de 19.402 servidores MCP con almacenamiento inseguro) y catalogado como MCP01 en el OWASP MCP Top 10.

Cómo se usa: pegale a esta herramienta el código o el archivo de configuración — revisa formatos reconocibles de credenciales reales (OpenAI, AWS, GitHub, Slack, Google, llaves PEM), asignaciones literales a variables/llaves de nombre de credencial, líneas ".env", y valores de reserva hardcodeados. Reconoce placeholders comunes para no marcarlos como riesgo.

Escudo de Deserialización
pickle, torch.load y yaml.load que pueden ejecutar código al "leer" datos

Funciones como pickle.load(), torch.load() (usada para cargar modelos de IA) o yaml.load() sin un cargador seguro no solo leen datos — pueden reconstruir objetos arbitrarios, y un objeto puede ejecutar código al reconstruirse. Basta con que esos bytes vengan de afuera. Caso real: CVE-2025-45146 (CVSS 9.8, crítico) en ModelCache, una librería de caché para agentes de IA. CVE-2025-32434 (CVSS 9.3) mostró que ni siquiera la mitigación recomendada por PyTorch bastaba sola en versiones anteriores a la 2.6.0.

Cómo se usa: pegale a esta herramienta el código que carga un dato serializado — revisa pickle/torch.load/yaml.load sin su forma segura, y la firma clásica de un payload malicioso (un método __reduce__ que ejecuta un comando del sistema).

Detector de Flujos Tóxicos

Ninguna herramienta individual tiene que estar rota: basta con juntar una que lea datos privados o contenido externo no confiable con una que pueda enviar/publicar datos hacia afuera, sin un paso de aprobación real entre medio. Escudo de Plantillas
Inyección en plantillas (SSTI): Jinja2, EJS, Handlebars, PromptTemplate de LangChain

Un motor de plantillas no solo "rellena espacios en blanco" — su lenguaje de expresiones puede llamar métodos y recorrer atributos de objetos. Si el TEXTO de la plantilla (no solo los datos que la rellenan) viene de afuera, un atacante puede escribir código dentro de la plantilla y terminar ejecutándolo en el servidor. Motivada por CVE-2026-33154 (CVSS 8.1, Dynaconf), un aviso en Agenta-AI (plataforma de evaluación de LLMs) y un aviso en LangChain mismo — el framework de agentes más usado — por inyección en plantillas de prompt.

Cómo se usa: pegale a esta herramienta el código que compila una plantilla — revisa si la fuente de la plantilla depende de una entrada externa en vez de un texto fijo, si falta un entorno sandboxeado, y si el código confunde "escapar la salida" (que no protege acá) con una defensa real.

Escudo de Código Dinámico
Ejecución de código no confiable (eval, Function, exec, vm.runInContext)

Una herramienta que evalúa código en tiempo de ejecución — eval(), Function() de JS, exec() de Python, vm.runInContext() de Node — a partir de un texto que no escribió el desarrollador (respuesta de un modelo, documento recuperado de un pipeline RAG, parámetro de herramienta) le da a quien controle ese texto ejecución arbitraria dentro del propio proceso del agente. Caso real: CVE-2026-26030 (CVSS 9.8, feb 2026) en Microsoft Semantic Kernel — un filtro de vector store interpolaba contenido recuperado de un documento indexado directo en un eval(), dando RCE a partir de datos envenenados de RAG. También detecta una falsa mitigación: vm2 está deprecada desde 2023 tras varias fugas de sandbox críticas.

Cómo se usa: pegale a esta herramienta el código que evalúa código dinámicamente — revisa si el argumento depende de una entrada externa en vez de un texto fijo, el patrón de "eval implícito" en setTimeout/setInterval con un string, y si el código usa vm2 (no confiable) en vez de isolated-vm (aislamiento real) para "sandboxear" la ejecución.

Escudo de Rebinding DNS
Falta de validación de Origen en el transporte HTTP/SSE de MCP

Un servidor MCP que expone su transporte HTTP/SSE sin validar el header Origin deja una puerta abierta a que una página web maliciosa haga que el navegador de la víctima hable directamente con ese servidor — que suele correr en localhost — como si fuera un cliente de confianza (rebinding DNS). Bindear solo a 127.0.0.1 no alcanza: es precisamente lo que el rebinding rompe. No es un bug aislado: el mismo patrón apareció de forma independiente en 2026 en los SDK oficiales de Rust (CVE-2026-42559, CVSS 8.8) y Java, y en mysql-mcp-server (Python).

Cómo se usa: pegale a esta herramienta el código que arma el transporte HTTP/SSE (el constructor del transporte o el registro de la ruta) — revisa si falta una validación reconocible del header Origin, y si el código confunde "solo escucha en localhost" (que no protege acá) con una defensa real contra rebinding.

Centinela de Autenticación
Endpoints MCP HTTP/SSE sin ninguna verificación de autenticación

Un servidor MCP que expone su transporte HTTP/SSE sin verificar autenticación antes de despachar la petición deja sus herramientas abiertas a cualquiera que sepa la URL — sin login, sin llave de API, sin token. Es el patrón más repetido entre los CVEs de MCP de 2026: CVE-2026-44895 (CVSS 9.1, crítico) en un servidor MCP de GitLab — sin autenticación y con CORS totalmente abierto, cualquiera podía invocar sus 86 herramientas (incluido borrar repos) usando el token del operador. Mismo patrón confirmado en Azure MCP Server (Microsoft), deepseek-mcp-server, NetLicensing-MCP, obsidian-web-mcp y mcp-documentation-server.

Cómo se usa: pegale a esta herramienta el código que arma el transporte HTTP/SSE (el constructor del transporte o el registro de la ruta) — revisa si falta una verificación reconocible de autenticación, y si además el CORS está completamente abierto, la combinación exacta que hizo explotable a CVE-2026-44895.

Escudo de Lanzamiento MCP (STDIO)
"command" sin validar en el transporte stdio de un cliente MCP

Cuando un cliente MCP se conecta por stdio (en vez de HTTP/SSE), los SDKs oficiales ejecutan el campo command de inmediato al construir la conexión — antes de que exista ninguna validación del protocolo MCP. Falla de diseño confirmada en 2026 en los cuatro SDKs oficiales (Python, TypeScript, Java, Rust). Caso real: CVE-2026-30623 en LiteLLM, donde un endpoint de "probar conexión" pasaba el command que mandaba el propio usuario directo al lanzador. También detecta brechas de "rehidratación" (se valida al guardar pero no al lanzar, el mismo patrón detrás de CVE-2026-30623 antes de su parche) y el bypass vía banderas de ejecución directa (-c/-e/--eval) aunque el binario esté en la lista blanca. También documentado en CVE-2026-22688 (Tencent WeKnora, CVSS 9.9).

Cómo se usa: pegale a esta herramienta el código que arma la conexión stdio de un cliente MCP (StdioClientTransport, StdioServerParameters) — revisa si el command depende de una entrada externa sin lista de lanzadores permitidos, si el lanzamiento viene de una configuración ya guardada sin revalidar, y si una bandera de ejecución directa esquiva una lista blanca que sí existe.

Una expresión regular con cuantificadores anidados (ej. (a+)+, (\s*\w+)*, (a|a)*) aplicada sobre una entrada sin tope de longitud puede colgar el proceso del agente entero con un solo string cuidadosamente armado (ReDoS, CWE-1333). Cómo se usa: pegale a esta herramienta el código que compila o aplica una expresión regular — revisa cuantificadores anidados aplicados contra una entrada variable sin tope de longitud ni motor con timeout/librería segura, y regex compilados dinámicamente desde una variable.

Escudo de Secuestro de Sesión
Sesiones validadas solo por ID, sin vínculo con el dueño

Un servidor que busca una sesión solo por el ID que trae la petición y confía en ella sin comparar ningún campo de dueño contra quien la presenta ahora, es vulnerable a secuestro de sesión: quien consiga ese ID hereda la sesión de otro cliente por completo. Motivada por CVE-2026-52869 (CVSS alto). También detecta IDs de sesión generados con poca entropía (Math.random(), Date.now() solo, un contador) — adivinables por fuerza bruta.

Cómo se usa: pegale a esta herramienta el código que busca o genera sesiones — revisa búsquedas por ID sin vínculo de dueño verificado después, y generación de IDs de sesión con poca entropía en vez de un generador criptográficamente seguro.

Validación de "aud" rota que deja pasar un token de otro servidor (fail-open)

Escudo de Secuestro de Sampling
Peticiones de sampling MCP cumplidas sin revisión humana

La función de "sampling" de MCP deja que un servidor le pida al modelo del cliente que genere una completion. Un cliente/host que cumple esa petición sin ningún paso reconocible de revisión humana — lo que la propia especificación de MCP recomienda exigir — deja que un servidor malicioso esconda instrucciones que el modelo sigue sin que nadie note nada raro, incluida la invocación encubierta de herramientas. Documentado en una investigación de Unit42 (Palo Alto Networks, octubre 2026).

Cómo se usa: pegale a esta herramienta el código del lado cliente/host que maneja peticiones de sampling entrantes — revisa ausencia de aprobación humana, invocación encubierta de herramientas (callTool) desde el mismo handler, y falta de tope de tokens (maxTokens).

Escudo de Esquema de Salida
SSRF + denegación de servicio vía validación de esquemas (CVE-2026-116686)

Cuando un cliente de MCP valida el resultado de una herramienta contra el outputSchema que el propio servidor le mandó, y usa jsonschema con su resolución de referencias por defecto, un servidor malicioso puede meter un $ref que apunte a una URL externa (SSRF). Peor: si esa llamada de red es síncrona dentro de una función async, un endpoint que nunca responde congela el event loop entero del proceso. Motivada por CVE-2026-116686 (CVSS 6.5) en el SDK oficial de Python de MCP.

Escudo de Agencia Excesiva
Acciones irreversibles sin confirmación exigida ni tope (OWASP LLM06)

Una herramienta que puede transferir, retirar, pagar o borrar sin que su esquema de entrada EXIJA un campo de confirmación, y/o sin ningún tope máximo en un campo de monto, es "agencia excesiva" (OWASP LLM06). Motivada directamente por el hackeo de Binance de octubre 2026 (6.300 millones de dólares): un solo dispositivo/credencial comprometido alcanzó un sistema con autoridad para autorizar retiros, sin ninguna aprobación independiente ni tope por operación.

Cómo se usa: pegale a esta herramienta un manifiesto MCP (mismo formato que audit_mcp_server) — revisa herramientas con una acción irreversible/de alto valor sin confirmación exigida en required, y campos de monto sin tope máximo (maximum/exclusiveMaximum).

Escudo de Suplantación de Llamada
Llamadas a herramienta extraídas de texto libre, no del campo estructurado ("Repeat-After-Me")

Las APIs de los modelos devuelven una llamada a herramienta en un campo estructurado y dedicado (tool_calls/function_call/tool_use) — se llena solo cuando el modelo invocó de verdad el mecanismo nativo. Documentado en octubre 2026 contra 6 frameworks de agentes: LangGraph, Microsoft Agent Framework, Google ADK 2.0, AutoGen, AWS Strands y CrewAI.
