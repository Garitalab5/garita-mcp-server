Detector de estado de servidor MCP compartido entre clientes

Un servidor MCP que crea UNA sola instancia de McpServer/Server al arrancar y la reutiliza para atender a TODOS los clientes que se conectan (en vez de crear una instancia nueva por sesión) puede mezclar el estado de un cliente con el de otro — una respuesta armada para el cliente A puede llegar al cliente B. Lo mismo pasa, incluso con instancias separadas, si hay una variable mutable a nivel de módulo (let/var, no const) que el callback de una herramienta registrada lee. Motivado por CVE-2026-25536 (CVSS 7.1): una falla real en el propio SDK oficial de TypeScript de MCP, donde una sola instancia de McpServer emparejada con StreamableHTTPServerTransport se reutilizaba entre clientes sin aislar el estado de la respuesta — catalogado por OWASP como "Context Injection and Over Sharing" (MCP10). Pegá acá el código que arma el transporte HTTP/SSE de tu servidor MCP.
