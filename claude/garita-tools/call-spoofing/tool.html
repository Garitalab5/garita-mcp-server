Detector del ataque "Repeat-After-Me" en orquestación de agentes

Las APIs de los modelos devuelven una llamada a herramienta en un campo estructurado y dedicado (tool_calls/function_call/tool_use) — se llena solo cuando el modelo de verdad decidió invocarla con el mecanismo nativo de function-calling. Varios frameworks de orquestación, en cambio, escanean el texto libre de la respuesta buscando un patrón que "parece" una llamada (TOOL_CALL:, un bloque ```json, <tool_call>) y lo ejecutan como si fuera real. El problema: ese texto puede venir de cualquier lado del contexto — un documento, una página web, el resultado de otra herramienta — y si el modelo simplemente lo "repite", el orquestador no tiene forma de distinguirlo de una decisión real. Documentado en octubre de 2026 (investigación de GBHackers) contra 6 frameworks de agentes de uso extendido: LangGraph, Microsoft Agent Framework, Google ADK 2.0, AutoGen, AWS Strands y CrewAI. Pegá acá el código de orquestación del lado del agente que interpreta la respuesta del modelo.

De uso libre

Es un análisis estático por patrones de texto — no ejecuta nada. Todo el análisis corre en tu navegador; el código que pegás acá no se envía a ningún lado.

Pegá el código y presioná "Analizar código".
No reemplaza un analizador de sintaxis (AST) real ni una auditoría de seguridad formal — mismo enfoque y mismas limitaciones que el Escudo de Secuestro de Sampling y el Escudo de Flujos Tóxicos. Límite conocido: las marcas de "llamada a herramienta en texto libre" (TOOL_CALL, FUNCTION_CALL, <tool_call>, bloque ```json) y el "campo estructurado" de la API (tool_calls, function_call, tool_use) se reconocen por nombres típicos — una convención muy distinta puede no detectarse.
